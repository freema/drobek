# drobek-module-hello

The example drobek platform module: what `npm create drobek-module@latest
hello` generates, plus a demo of the module contract 1.1 slots — the slot
`hello.greeter` other modules contribute to and the module's own error code
`unknown_greeter`. The dev stack runs it (`DROBEK_MODULES=hello,…`).

- `GET /__drobek/v1/hello` → `{ greeting, message, waves, signed }`
- `POST /__drobek/v1/hello/wave` → `{ waves }` (rate-limited per visitor IP)
- `GET /__drobek/v1/hello/whoami` → the visitor as `ctx.principal`
- `GET /__drobek/v1/hello/greet?name=…&greeter=<id>` → `{ text, greeter }`
- `drobek.hello.ping()` / `wave(name)` / `whoami()` / `greet(name, greeter?)`
- config `{ greeting, excited }` — a greeting change needs the owner's OK.

## Develop

```sh
pnpm --filter drobek-module-hello test        # the routes (PGlite) + checkSkill
pnpm --filter drobek-module-hello check       # the SKILL.md gate alone
pnpm --filter drobek-module-hello build
```

In the drobek repository the example links the workspace `@drobek/modules`;
a module generated by `create-drobek-module` depends on the published
package instead (a peer dependency — the server provides it).

## Install on a drobek server

A module outside this repository is installed with
`task selfhost:module:add -- <npm spec or tarball URL>` and listed in
`DROBEK_MODULES`. The guide:
[docs/MODULES.md → Writing a module](../../docs/MODULES.md#writing-a-module).
